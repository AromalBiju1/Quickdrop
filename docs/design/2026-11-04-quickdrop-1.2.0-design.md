# QuickDrop 1.2.0 Design

**Date:** 2026-11-04
**Status:** Approved design, pending implementation plan
**Target version:** 1.2.0 (build 4)
**Supersedes:** the `/api/text` + fallback proposal discussed before approval

---

## Summary

QuickDrop 1.2.0 adds three things:

1. **Dark mode** with System / Light / Dark control, built on a theme-aware palette.
2. **Text send** from Android, Linux and Windows, plus the browser receiver, using the existing upload endpoint with a `X-Text-Snippet` marker.
3. **Subtle motion** for tab changes, progress, panels, history and theme switching, respecting the OS reduced-motion setting.

The release keeps the existing wire protocol. File transfers, discovery, notifications and history remain compatible with 1.1.0 in every direction. Text sent to a 1.1.0 receiver arrives as a normal `.txt` file.

---

## Goals

- Ship a dark theme that matches the quality of the light theme, not an inverted approximation.
- Let a user send a link or snippet to a nearby device and paste it immediately on the other side.
- Make the interface feel smoother without adding bounce, confetti or extra dependencies.
- Preserve 1.1.0 interoperability for everything except the new text-specific treatment.

## Non-goals

- iOS and macOS builds.
- End-to-end encryption or authentication.
- Syncing text through history across devices.
- Rich text, Markdown rendering or code highlighting.
- A separate text protocol version or endpoint.
- Redesigning the light theme.

---

## Current state

- `lib/ui/quickdrop_theme.dart` defines `QuickDropColors` as static constants and `QuickDropTheme.lightTheme`; `darkTheme` is an alias for the light theme.
- Roughly 400 `QuickDropColors.*` references exist across `lib/ui`.
- `QuickDropText` styles embed light-mode colors and are used directly in 17 places.
- `AppSettings` stores `device_name`, `auto_copy_images` and `notifications` in `settings.json`.
- `QuickDropController` is created inside `QuickDropScreen`; `QuickDropApp` owns `MaterialApp`.
- `TransferServer` exposes `POST /api/transfer`, writes the body to a `.part` file, verifies `Content-Length`, renames it and records `TransferItem` history.
- `TransferItem` has no type field; every entry is assumed to be a file.
- The browser receiver is a self-contained HTML page inside `transfer_server.dart` and is already dark.
- Animations are limited to a few `AnimatedContainer` widgets and the top notice.

## 1. Dark mode

### 1.1 Palette as a theme extension

Replace the static color class with a `ThemeExtension`:

```dart
@immutable
class QuickDropPalette extends ThemeExtension<QuickDropPalette> {
  final Color background;
  final Color backgroundWarm;
  final Color surface;
  final Color surfaceSubtle;
  final Color surfaceMuted;
  final Color border;
  final Color borderStrong;

  final Color emerald;
  final Color emeraldDark;
  final Color emeraldDeep;
  final Color emeraldSoft;
  final Color emeraldBorder;

  final Color onyx; // inverse surface for tooltips and snackbars
  final Color textPrimary;
  final Color textSecondary;
  final Color textMuted;
  final Color textFaint;

  final Color rose;
  final Color roseDark;
  final Color roseSoft;
  final Color roseBorder;
  final Color amber;
  final Color amberSoft;
  final Color amberBorder;
  final Color blue;
  final Color blueSoft;
  final Color violet;
  final Color violetSoft;

  final Color shadowSoft;
  final Color shadowRaised;

  // copyWith, lerp, light and dark const instances
}
```

Access:

```dart
extension QuickDropUi on BuildContext {
  QuickDropPalette get qd =>
      Theme.of(this).extension<QuickDropPalette>() ?? QuickDropPalette.light;

  TextTheme get text => Theme.of(this).textTheme;
}
```

`QuickDropTheme.light` and `QuickDropTheme.dark` each build a `ThemeData` with `extensions: [palette]` and matching `ColorScheme`, `CardTheme`, buttons, inputs, dialogs, snackbars, tooltips and menus.

### 1.2 Typography

`QuickDropText` no longer carries colors. The styles move into the `TextTheme` of each `ThemeData`, with colors taken from the active palette. The 17 direct `QuickDropText.*` uses in widgets switch to `context.text.<style>`.

### 1.3 Migration rules

- `QuickDropColors.background` → `context.qd.background`, and so on for every field.
- `Colors.white` and `Colors.black` are audited individually:
  - on-accent text and icons stay white;
  - surface-like uses move to `context.qd.surface`;
  - translucent black scrims stay as-is.
- Shadows come from `shadowSoft` / `shadowRaised`.
- No widget keeps a compile-time color that must change with the theme.
- The browser receiver is untouched because it is already dark.

### 1.5 Theme control and persistence

- `AppSettings` gains `themeMode` (`ThemeMode`), serialized as `"system"`, `"light"` or `"dark"` under the key `theme_mode`.
- Missing or invalid values default to `ThemeMode.system`, so existing `settings.json` files load unchanged.
- `SettingsDialog` gains an **Appearance** section with three segmented options: System, Light, Dark. It reads the current mode on open and includes it in the saved `AppSettings`.
- `QuickDropApp` holds the active `ThemeMode` in state, initialized from the loaded settings. `QuickDropScreen` receives an `onThemeModeChanged` callback and forwards it after a successful save.
- `MaterialApp` is configured with `theme: QuickDropTheme.light`, `darkTheme: QuickDropTheme.dark`, and `themeMode: _themeMode`. Material's built-in theme animation handles the crossfade.
- Android status and navigation bar icon brightness follow the active palette through `AnnotatedRegion<SystemUiOverlayStyle>`.

### 1.6 Edge cases

- A settings file with an unknown mode falls back to System.
- A user changing the mode sees the Settings dialog itself update when the dialog closes, because the dialog is rebuilt by the new theme.
- Widget tests that assume light colors must pass an explicit theme or set `themeMode: light`.
- Golden tests are not part of this release; visual checks are manual on Android, Linux and Windows.

## 2. Text send

### 2.1 Wire format

Text uses the existing endpoint. No new route, no JSON body, no fallback branch.

```http
POST /api/transfer HTTP/1.1
Host: 192.168.1.42:53318
X-File-Name: QuickDrop-text-20261104-143012.txt
X-Sender-Name: Aromal
X-Text-Snippet: 1
Content-Type: text/plain; charset=utf-8
Content-Length: 84

https://example.com/some/link
```

- The request body is the UTF-8 text itself.
- `X-File-Name` supplies a readable filename for receivers that do not understand the header.
- `X-Text-Snippet: 1` marks the upload as text.

### 2.2 Receiver behavior

`TransferServer._handleIncomingTransfer` checks `X-Text-Snippet` before writing:

- If the header is absent, existing file behavior is unchanged.
- If present:
  - Reject `Content-Length > 65,536` with `413 Payload Too Large`.
  - Reject an empty or whitespace-only body with `400 Bad Request`.
  - Enforce the same limit while streaming when `Content-Length` is absent; abort and delete the `.part` file if exceeded.
  - Save the body as UTF-8 in the normal save directory, using the sanitized `X-File-Name` with `.txt` ensured. On Android, publish through MediaStore exactly like a text file.
  - Copy the text to the clipboard through `PlatformIntegrations.copyTextToClipboard`.
  - On Linux and Windows, show a desktop notification titled `QuickDrop • Text received` with an 80-character preview. Android has no system notification path in this app, so the shared in-app top notice is the alert there.
  - Record a `TransferItem` with `kind = text`, `preview` set, and `filePath` pointing at the `.txt`.
  - Respond with `{status, file, path, size, clipboard}` and `kind: "text"`.

If clipboard copying fails, the file and history entry are still kept and the response reports `clipboard: false`.

### 2.3 Sender behavior

`TransferClient.sendText`:

```dart
static Future<TransferResult> sendText({
  required DevicePeer targetPeer,
  required String text,
  required String senderName,
})
```

- Encode the text as UTF-8 and POST it to `/api/transfer` with the headers above.
- No temporary file is written.
- Timeout: 10 seconds.
- Empty text is rejected before the request.
- The text limit is 16,000 characters (Unicode code units) and 64 KiB of UTF-8.
- Success and failure messages reuse `TransferResult`.
- Old peers need no special handling: 1.1.0 ignores the header and saves the `.txt`.

`QuickDropController.sendTextToPeer` adds an outgoing `TransferItem(kind: text, preview: ...)` on success and leaves the normal send summary untouched. Text sends do not participate in file batches.

### 2.4 History model

`TransferItem` gains:

```dart
enum TransferKind { file, text }
final TransferKind kind;   // defaults to file
final String? preview;     // first 500 characters for text
```

Serialization:

- `"kind": "text"` / `"file"`.
- `"preview"` only for text.
- Old entries without `kind` load as `file`.
- Full text is not stored in `history.json`; the `.txt` is the source of truth and `preview` is the display/fallback copy.

The history tile for a text entry shows a notes icon, the first line of the preview, the sender and time, and a **Copy text** action. `Copy text` reads the `.txt` if it still exists and otherwise copies `preview`. The existing **Open file** and **Show in folder** actions remain.

### 2.5 Native UI

- `SendPanel` gains a **Text** action next to **Choose files** and **Photos**, shown in both the empty drop zone and the selection footer.
- Tapping it opens `TextComposerSheet`, a bottom sheet containing:
  - a multiline `TextField` (6 visible lines, max 16,000 characters);
  - a **Paste** button using `Clipboard.getData`;
  - a character counter;
  - a **Send** button disabled when empty, over the limit, or no peer is selected;
  - the selected device name, or a prompt to select one.
- On success the sheet closes, a top notice confirms delivery and an outgoing history entry appears.
- On failure the sheet stays open and shows the error inline; the text is not lost.

### 2.6 Browser receiver

The `/web` page gains a **Send text** card:

- textarea with counter, maximum 16,000 characters;
- Send button;
- POST to `/api/transfer` via the existing XHR pattern, with `X-Text-Snippet: 1`, `X-File-Name: QuickDrop-text-<timestamp>.txt` and `X-Sender-Name: Browser`;
- inline success/error feedback;
- the text is cleared after a successful send.

### 2.7 Compatibility matrix

| Sender | Receiver | Result |
| --- | --- | --- |
| 1.2.0 | 1.2.0 | Saved, copied to clipboard, text history, text notification |
| 1.2.0 | 1.1.0 | Saved as a normal `.txt`, file notification, no clipboard |
| 1.1.0 | 1.2.0 | Unchanged file transfer behavior |
| 1.1.0 | 1.1.0 | Unchanged |
| Browser 1.2.0 | 1.2.0 | Same as 1.2.0 sender |
| Browser 1.2.0 | 1.1.0 | Saved as a normal `.txt` |

Discovery, file transfers, notifications and history remain compatible across all combinations.

### 2.8 Error handling

| Case | Behavior |
| --- | --- |
| Empty text | Send disabled; server returns 400 if forced |
| Over 16,000 characters | Send disabled with counter warning; server returns 413 |
| Clipboard unavailable | Text still saved; notice says it was saved without clipboard |
| Receiver older than 1.2.0 | Text arrives as `.txt` |
| Receiver offline | Existing connection error message; sheet stays open |
| Disk write failure | 500 response, `.part` deleted, no history entry |
| Notification failure | Ignored; transfer still succeeds |

## 3. Animations

### 3.1 Motion helper

Add `lib/ui/quickdrop_motion.dart`:

```dart
class QuickDropMotion {
  static bool reduced(BuildContext context) =>
      MediaQuery.maybeOf(context)?.disableAnimations ?? false;

  static Duration duration(BuildContext context, Duration duration) =>
      reduced(context) ? Duration.zero : duration;
}
```

Every new animation uses this helper. Existing `AnimatedContainer` widgets are left as-is unless they visibly conflict.

### 3.2 Specific motion

- **Tab bodies:** `AnimatedSwitcher`, 180 ms, fade plus a 6 px vertical slide, keyed by tab index. Scroll position reset behavior is unchanged.
- **Bottom navigation:** existing `AnimatedContainer` selection, normalized to 180 ms and `Curves.easeOutCubic`.
- **Progress:** `TweenAnimationBuilder<double>` around the existing linear and circular indicators, 240 ms. Under reduced motion the value jumps.
- **Send result panel and device list:** `AnimatedSize` with 200 ms, so appearing content does not snap.
- **History:** filter changes crossfade with `AnimatedSwitcher`; a newly received row fades and expands once. `AnimatedList` is not used because the list is grouped by date and includes batch sections.
- **Top notice:** keep the existing motion, align duration and curve with the rest.
- **Theme change:** Material's built-in theme animation; no custom work.

### 3.3 Constraints

- No new packages.
- No animation on the first frame after launch.
- No looping or attention-seeking motion.
- Animations must not delay input or obscure the transfer controls.
- Verify on the RMX5101 at 60 Hz; if jank appears, reduce the affected animation rather than adding a package.

## 5. Testing plan

- **Theme:** palette `lerp`, light and dark extensions present, settings round-trip including legacy JSON without `theme_mode`.
- **Widgets:** pump the app in light and dark, assert the scaffold and a card resolve the expected palette; render the settings dialog in both modes.
- **Text server:** start `TransferServer` with a temporary save directory and assert:
  - text upload with the header saves a `.txt`, records `kind = text` and a preview;
  - an upload without the header keeps the existing file behavior;
  - empty body returns 400;
  - body over 64 KiB returns 413;
  - `clipboard: false` is handled without losing the file.
- **Text client:** run a local `HttpServer`, call `sendText`, assert the path, headers and raw UTF-8 body.
- **History:** old JSON defaults to `file`; text entries round-trip `kind` and `preview`.
- **Composer:** empty state disables Send, counter updates, Paste inserts clipboard text, oversized text disables Send.
- **Motion:** helper returns zero under `disableAnimations`; tab switch still renders the correct content.
- **Manual:** Android ↔ Linux and Android ↔ Windows text in both directions, clipboard paste, history actions, browser text, dark mode on all three platforms, reduced-motion toggle.

Existing 45 tests must continue to pass.

## 7. Risks

- **Theme migration misses:** a hardcoded color that only looks wrong in dark mode. Mitigation: grep for `QuickDropColors`, `QuickDropText`, `Colors.` and `Color(0x` after migration, then visually inspect every tab, dialog and popup in both themes.
- **Clipboard differences:** Linux clipboard behavior varies by compositor. Mitigation: use Flutter's text clipboard first; if it fails, save the file and report `clipboard: false`.
- **Text treated as a file by old peers:** expected and documented; no code fix.
- **History growth:** previews are capped at 500 characters, full text stays on disk.
- **Animation jank on low-end Android:** keep durations short and test on the RMX5101.
- **1.2.0 text size limits:** enforced on both client and server so a modified client cannot write unbounded data.

---

## 8. Resolved decisions

- Dark mode follows the system by default with a manual override.
- Received text is copied to the clipboard, saved as `.txt` and recorded in history.
- Text is composed in a sheet with a paste button.
- The browser receiver can send text.
- Text uses the existing `/api/transfer` endpoint with `X-Text-Snippet`; no new endpoint, no fallback.
- Animations are subtle and use Flutter built-ins only.
- The spec lives in `docs/design/`, not `docs/superpowers/`.
